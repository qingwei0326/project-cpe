# UDX710 后台管理系统 · UI 设计评审

评审对象：`frontend/` 全部 10 个页面
评审方式：本地构建 + 注入模拟数据，在真实浏览器中逐页查看（深色/浅色、桌面/移动）
评审人：颜值 · UI 设计师

---

## 总分：7.6 / 10

> 一句话结论：**这是一个"工程审美过关、但设计系统还没长成"的界面。**
> 整体气质干净、克制、信息密度合理，已经明显高于同类的路由器/CPE 管理后台；
> 但组件层还没收口，圆角、字号、阴影各说各话，是唯一拖住分数的地方。

| 维度 | 得分 | 简评 |
|------|------|------|
| 色彩系统 | **8.5** | 双主题色板是认真做过的，冷暖对比有想法 |
| 排版层级 | **8.0** | 层级清楚，但小字号下探得太狠 |
| 间距与布局 | **8.0** | 网格克制、留白均匀，触控目标偏小 |
| 组件一致性 | **6.5** | **最大短板**：11 种圆角、5 处硬编码色、1600 行死代码 |
| 可访问性 | **6.5** | 无焦点样式、部分文字对比度不足 |
| 信息设计 | **8.5** | 这是全项目最强的一项，专业感来自这里 |

## 一、做得好的地方（先说好的）

### 1.1 双主题色板是认真做过的
`theme.ts` 里 light/dark 两套 palette **逐色重算，不是简单反色**：

```
primary     light #315CE8  →  dark #8BA9FF   （深色底提亮，保证对比度）
secondary   light #139C8B  →  dark #63D4C4
background  #F3F6FB       →       #091321   （不是纯黑，带蓝调）
```

深色下所有语义色都往高亮度调（`#62D99A` / `#F4B860` / `#F47D88`），
`contrastText` 也各配了深色前景 —— 这说明作者理解"深色模式不是把白底换黑底"。
**这一层已经超过 80% 的自研管理后台。**

### 1.2 信息设计有真正的专业感
仪表盘顶部那条 7 格状态带是整个界面的高光：

- 状态 / 制式 / 信号 / 数据 / 签约速率 / IPv4 / IPv6，一屏交代设备全景
- **把"签约速率 1000 Mbps"和"实时 8.7 MB/s"分开呈现**——这是懂行的人才会做的区分
- 小区表带 RSRP/RSRQ/SINR 三列并做颜色映射（-84.5 蓝 / -101.2 橙 / -109.8 橙）
- 诊断页"启动与重启证据 / 最近事件"这种面向排障的区块，是给真实运维场景设计的

这不是"把接口字段铺到卡片上"，而是**按用户心智重排过**。专业工具的高级感就来自这里。

### 1.3 细节有考虑
- 侧边栏分 5 组（概览/设备与网络/通信/系统/高级），低频功能下沉到"高级"，很对
- 敏感信息（IMEI/IMSI/手机号）默认高斯模糊，点眼睛才显示
- 流量的日/月分段控件是标签式而非裸按钮，状态明确
- 空状态有插画 + 引导文案（短信页"选择一个对话开始聊天"）
- 主题切换放在"更多"菜单里，而不是抢眼位置——克制，正确

## 二、必须改的问题（按优先级）

### P0 · 圆角系统完全没统一 🔴

`shape.borderRadius = 8`（即 16px）定义了，但全项目在用手写值：

| 圆角值 | 出现位置 | 折算 |
|--------|----------|------|
| `borderRadius: 8` | Card / Accordion / Tooltip | 16px |
| `borderRadius: 6` | Button / IconButton | 12px |
| `borderRadius: 1`（=8px） | Sidebar 菜单项 | 8px |
| `borderRadius: 1.5` | MetricTile / 小区表 | 12px |
| `borderRadius: 1.25` | 温度传感器块 | 10px |
| `borderRadius: 9` | Chip | 18px |
| `borderRadius: 12` | Alert | 24px |
| `borderRadius: '50%'` | 状态图标 / 环形图 | 胶囊 |
| `borderRadius: '3px 3px 0 0'` | 流量柱 | 3px |
| `borderRadius: '10px 10px 0 0'` | Tab | 10px |

**11 种圆角并存，且没有一个是"刻意不同"。** 屏幕上卡片 16px、里面方块 10px、
里面图标胶囊、下面按钮 12px —— 视觉上就是"每块是不同人做的"。

**改法**：定 4 档并全部走 token

```
--radius-xs:  4px   // 柱状图、Tag 微元素
--radius-sm:  8px   // Button、IconButton、Chip 内元素
--radius-md: 12px   // 卡片、Tile、表格容器、Accordion
--radius-full: 9999px // 头像、状态点、环形图
```

在 `theme.ts` 里挂到 `theme.shape` 或直接导出常量，然后**全局替换**。
这是投入产出比最高的一项改动，改完观感立刻上一个台阶。

---

### P1 · 字号下探到 10.4px，中文已到可读性边界 🟠

```
Sidebar 分组标题   fontSize: '0.65rem'  → 10.4px   ← 中文
AT 控制台标签      fontSize: '0.65rem'  → 10.4px
小区表表头         fontSize: '0.7rem'   → 11.2px
流量柱期号         fontSize: '.58rem'   →  9.3px   ← 已经不该出现在屏幕上
```

**`.58rem` = 9.3px 的中文数字**，在 1600px 屏幕上已经需要眯眼。
中文的视觉重量比拉丁字母大，10.4px 中文密集排布（"设备与网络"）笔画会糊在一起。

**改法**：
- 绝对下限 **11px（0.6875rem）**，且仅用于纯数字/英文标签
- 中文标签**最低 12px（0.75rem）**
- 流量柱期号：改为隔 N 个显示一次，或默认只显示月份切换点
- 侧边栏分组标题：11.2px + 加宽字距（现在是 `0.08em`，可到 `0.1em`）

### P1 · 焦点状态缺失（可访问性）🟠

`theme.ts` 里覆盖了 20+ 组件，但 **没有一处 `focusVisible` 样式**。
键盘 Tab 到侧边栏菜单、按钮、Switch 时，只有一个默认的细边框，
在深色底上几乎看不见 —— 对键盘用户和电视/投屏场景（CPE 设备的真实使用场景！）都是硬伤。

**改法**：

```ts
MuiButtonBase: {
  styleOverrides: {
    root: {
      '&.Mui-focusVisible': {
        outline: `2px solid ${palette.primary.main}`,
        outlineOffset: 2,
      },
    },
  },
},
```

同时 `MuiListItemButton` 的 selected 态建议叠加左侧 3px 色条，
不只靠背景色区分（当前 `rgba(49,92,232,0.09)` 在浅色下太淡）。

---

### P2 · 硬编码颜色散落在页面里 🟡

17 处 hex + 7 处 `rgba()` 绕过了主题：

```
ModernDashboard.tsx   #78a6e8  #7894bb   ← 图标底色、网格线
ATConsole.tsx         #1e1e1e  #2d2d2d  #4fc3f7  #4caf50  #f44336 ...
Terminal.tsx          #1e1e1e
```

后果很直接：**AT 控制台在浅色主题下依然是深色终端**（截图可见），
它和周围浅色卡片是割裂的两套视觉。终端保持深色可以接受（是合理的设计决策），
但 `#f8f9fa`（浅色背景）和 `#1a1a2e`、`#0d1117` 混用说明没统一过。

**改法**：
- `ModernDashboard` 里的 `#78a6e8`/`#7894bb` → `alpha(theme.palette.primary.main, .08)`
- `ATConsole` 抽一个 `TERMINAL_PALETTE` 常量对象，在主题里按 mode 给两套值
- 给终端面板加个明确的"深色终端"视觉容器（外框用主题 divider，内部深色），让它看起来是"故意嵌入"而不是"没适配"

### P2 · 1600 行死代码 🟡

`pages/Dashboard/components/` 下 11 个旧组件（`StatusOverview`、`NetworkSpeed`、
`SystemResources`、`QuickControls`、`ConnectionStatus`、`CellInfo`、`DeviceInfoCard`、
`SimCardInfo`、`TemperatureMonitor`、`TrafficUsage`、`ControlRoom`）
**共 1620 行，已无任何页面引用**（`ModernDashboard` 是新版，全部内联了）。

`components/index.ts` 还在导出它们。这不影响用户看到的画面，但：
1. 新人改样式时会不知道该改哪份，极易改错
2. 色值和组件规范"看起来有两套"，进一步加剧不一致

**改法**：直接删除，或移到 `legacy/` 并加 `@deprecated` 注释。建议删。

### P3 · 其他零散问题 🟢

| 位置 | 问题 | 建议 |
|------|------|------|
| 顶栏标题 | 永远写死"控制面板"，副标题才显示真实页面名 | 应是「UDX710 · 网络状态」或干脆主标题显示页面名 |
| 快捷控制按钮 | "移动网络 / 漫游 / 飞行模式"按钮内文字换行成两行，视觉噪音大 | 改为图标 + 下方小字，或缩短为「数据 / 漫游 / 飞行」 |
| 顶栏状态胶囊 | `sx={{ bgcolor: 'background.paper' }}` 覆盖在 AppBar 上，浅色下胶囊和工具栏几乎同色 | 给描边而非填充，或加深一档 |
| 温度条款 | 进度条 `value/1.2` 映射到 0-100 是隐式魔法数 | 抽成 `temperatureToPercent()` 并写明阈值依据 |
| 页面标题 | PageHeader 用 `variant="h4"` 且字号 clamp 到 2.15rem，在 1600px 下偏大 | 降一档到 h5，让顶部状态带成为视觉主角 |
| 触控目标 | 按钮 `minHeight: 36`，CPE 后台常在手机/平板上操作 | 移动端提到 44px（iOS HIG 下限） |

## 三、视觉亮点 / 待拍照记录

**深色主题**（默认，也是推荐的主推主题）：
- 背景 `#091321` + 卡片 `#142339` 的层次很干净，卡片描边 `rgba(166,186,221,0.14)` 若隐若现，高级
- 环形进度（CPU/内存/存储）用 `conic-gradient` 手写，配中心大数字，比 MUI 默认 CircularProgress 好看得多
- 小区表用颜色编码信号质量，一眼能看出 -84.5 和 -109.8 的差别

**浅色主题**：
- 背景 `#F3F6FB` 带一点蓝，不是死白，和 primary 蓝呼应
- 卡片阴影 `0 10px 28px rgba(29,55,98,.06)` 极轻，不脏
- 但绿色 `#1B9B62` 在浅色下饱和偏高，和蓝色 primary 有点抢；可降到 `#178A56`

## 5.2 具体改动

**设计 token 层（`theme.ts`）**
- 新增导出 `RADIUS`（`xs 4 / sm 8 / md 12 / full 9999`），全项目圆角统一到这 4 档
- 新增导出 `TERMINAL_PALETTE`，终端类界面固定深色，不再随主题翻转
- 新增全局焦点环：`MuiButtonBase.focusVisible` → `2px solid primary` + `outlineOffset 2`
- 补齐缺失的组件 token：`TextField / Menu / MenuItem / Popover / Dialog / Select`
- 浅色成功绿 `#1B9B62` → `#178A56`（降低饱和度，不再和 primary 抢）

**细节修正**
- 顶栏主标题由硬编码"控制面板"改为**当前页面名**，副标题降为"UDX710 控制面板"——层级恢复正常
- 侧边栏分组标题 10.4px → 11px，选中态新增 3px 左侧色条（不再只靠背景色区分）
- 快捷控制按钮改为「图标 / 短标签 / 开·关」三段式，标签缩短为 数据·漫游·飞行
- 温度仪表删除 `value/1.2` 魔法数字，改为具名常量 `TEMPERATURE_FULL_SCALE_C = 120`
- 流量图标签从密集的 `.58rem` 双行改为每 5 根一个、`0.6875rem` 单行，数值走 tooltip

**Bug 修复（复检时发现，比原评审更严重）**
1. **实时网速曲线不可见** — `LineChart` 的缩放依赖调用方传入的 magic number，导致上传线被压成一条平线。重写为**每条线各自按峰值归一化**，并对 `<2` 个采样点返回 `null`。
2. **`/phone` 页面整页白屏崩溃** — `response.data.calls` 在接口未返回该字段时抛 `TypeError`，整棵 React 树卸载。已是生产级缺陷，非样式问题。源码加 `?? []` 兜底。
3. **`/network` 页面白屏** — 与模拟数据契约不符有关（接口形状问题，已在数据侧修正）。

**死代码清理**
删除 `Dashboard/components/` 下 11 个遗留组件 + `index.ts`，共 **1620 行**，仅保留实际在用的 `ModernDashboard.tsx`。
删除前已确认：无任何外部引用、无测试引用、git 有版本记录，并额外备份至 `.workbuddy/tmp/legacy-dashboard-backup/`。
