project-cpe · UI 重设计方案

面向 UDX710 5G CPE 管理后台。所有接口清单与页面数据均来自实机 192.168.66.1 的实测返回值，非假设。

固件 v3.3.8 · 38f367e-dirty · 后端 61 个路由 · 前端 74 个方法 · 2026-09-20

一、先说清楚：现在为什么不好看

我进设备把 61 个路由全打了一遍，结论有点反直觉 —— 功能几乎没缺。前端 74 个 API 方法里有 72 个在页面里被真实调用，覆盖率接近 100%。所以问题不在"少做了什么"，而在下面四条：

1. 没有视觉焦点，所有信息等权

实测最有价值的数据是「运营商 + 5G + 信号 + 实时速率 + 今日流量」，但现在它们和 IMEI、MTU、rx_errors 排在同一张表里，用同一种字号、同一种灰。用户打开页面不知道先看哪。

2. 主色只出现在图标上，页面 90% 面积发灰

原主题主色是蓝紫，只用在侧边栏图标和几个按钮上，数据区全是中性色。青绿 #2DD4BF 作为主色后，数据本身可以被强调，而不是靠加边框。

3. 卡片之间只靠 1px 描边区分

页面底 #0B1220、卡片 #141E33、次级卡片 #111A2C 三级明度，层次靠明度而非描边。描边只保留 rgba(148,173,214,.12) 这种极淡的。

4. 信息架构严重失衡

Network.tsx 一个文件 1708 行，塞了蜂窝/频段锁定/小区锁定/扫网/APN/接口/流量七件事；而真正该当主角的仪表盘只有 48 行。这是"看起来乱"的根因，不是配色。

文案本地化

模组经 AT+COPS 返回的运营商名是固件原始串（实机为 CHN-UNICOM），不能直接显示。统一走 utils/carriers.ts 的三级解析：

优先级依据说明
1PLMN（MCC+MNC）精确查表最可靠，固件改名也不受影响。已收录中国大陆全量 + 中国港澳台 + 约 50 家常见国际漫游运营商
2名称精确别名覆盖 CHN-UNICOM / CMCC / CTCC 这类缩写与大小写、连字符变体
3名称关键词包含处理 CHN-UNICOM (LTE) 这类带后缀的写法；特定词排前，避免「Chunghwa Telecom」被通用词 telecom 误判
4原样返回三级都没命中就显示固件原名，绝不臆造翻译
展示规则：主名称用中文，固件原名降为副标题灰色小字（如「中国联通」下方一行 CHN-UNICOM · 460-01）。这样既不用用户自己翻译，又保留了排障时对照固件的线索。运营商扫描列表同样适用。

六、剩余页面规范

剩下 6 个页面结构相近，按同一套「分区卡片」模式实现，不再逐张出图。每页统一为：页头（标题 + 一句状态）→ 主区（1–2 张主卡）→ 次要区（折叠 / 表格）→ 危险操作区（置底，红色描边）。

页面主区关键规则
短信管理会话列表（左） + 对话流（右） + 底部发送框当前实机 0 条。空状态必须给出「发送第一条短信」入口，不能只写「暂无数据」。发送框固定底部不随滚动移动。
设备信息身份卡（IMEI / IMEISV / 制造商 / 型号） + SIM 卡（ICCID / IMSI / 号码 / 短信中心）IMEI 等长串用 tabular-nums 并允许点选复制。卡槽切换是危险操作，需二次确认。
USB 模式当前模式大卡 + 模式选择网格 + configfs 诊断快照实机 needs_reboot:true，必须在页面顶部常驻一条琥珀色提示条「配置将在重启后生效」，并提供重启按钮。诊断快照默认折叠。
通知自动化开关 + URL 输入 + 短信/来电模板编辑 + 测试发送当前未启用。启用开关与 URL 校验联动：URL 为空时不许开启。模板变量 {{phone_number}} 做成可点击插入的标签。
OTA 更新当前版本卡 + 上传区 + 进度条 + 应用/取消上传 50MB 上限要有明确提示与实时百分比。固件 38f367e-dirty 表示工作区有未提交改动，应显示琥珀色标记。
诊断状态总览 + 日志查看器 + 重启日志用等宽字体、深色底、可搜索。重启按钮必须是红色描边并二次确认，不与其它操作并列。
危险操作（重启、卡槽切换、清空短信、清空通话记录、OTA 应用）统一规范：红色描边按钮 + 点击后弹确认框 + 确认框里写明后果。现在这些都和普通按钮长得一样。
